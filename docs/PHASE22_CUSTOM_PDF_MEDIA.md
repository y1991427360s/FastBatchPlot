# 阶段 22：中望 PDF 独立纸张配置

本阶段仅处理 PDF 打印，不包含图章、签名或授权。原版帮助第 1 页明确包含自动生成任意尺寸纸张；此前两宿主只能匹配驱动已有介质，没有自动生成配置的路径。

## 实现范围

- 只在中望 PDF 文件输出或 PDF 预览找不到完整匹配介质时尝试生成。已有匹配纸张沿用原流程；实体打印和其他格式不使用此路径。
- 介质枚举出现读取错误时直接报错，不把配置损坏解释为缺纸张。
- 从 SDK 设备列表中定位所选设备唯一的真实 PC5 路径，限定已识别的中望原生 PDF 驱动。不使用项目中复制自原版的专有打印资源。
- 核心纯文件服务按最终纸张宽高（含留白）生成独立 PC5 和仅含一张纸的 PMP。配置保存在临时目录的随机子目录，源 PC5/PMP、CAD 搜索路径和默认设备均不改写。
- 新配置请求零边距。实际可打印区域必须由宿主回读确认，不能把文件中写了零边距视为驱动已经支持。
- 源配置严格按 GBK 解码并保留有效设置；尺寸用固定小数和不随系统区域设置变化的格式。配置文件在引擎使用期保持读锁，只清理本次明确创建的文件，不递归清理其他内容。
- 设置独立配置后先检查纸张标识和实测尺寸；打印验证后再次检查最终配置的完整路径、介质及打印设置。所有介质匹配、内容容纳与最终 PDF 尺寸的容差统一为 0.01 mm。已复现并修复旧 0.5 mm 容差把每边 0.1 mm 正留白吞掉、放过 0.2 mm 内容裁切的问题。
- 最终 PDF 仍要经过页数、尺寸、裁切和旋转检查，才提交正式文件。
- 若 PDF 已成功提交而临时配置清理失败，保留成功状态并在列表、完成摘要和历史结果中展示警告及残留目录；不会将已生成页作为失败页重复提交。

## SDK 与文件证据

中望 PC5 为 INI；安装附带 PMP 为 GBK 文本，包含 Meta 和 user 两节。官方样本有 72 张连续编号的自定义纸，每张含 12 个字段。静态检查脚本和摘要在 `audit-evidence/phase22-inspect-zwcad-pc5.py`、`phase22-zwcad-pc5-inspection.json`。

两宿主 SDK 均提供自定义介质匹配策略枚举，但没有找到直接设置任意毫米宽高的公开属性。PlotPaperSize 只读，SetClosestMediaName 的存在不能证明它会新建纸张。本阶段不伪造这类能力。

中望最终介质检查使用 PlotInfo.ValidatedSettings 与 ValidatedConfig.GetMediaBounds。后者给出可打印区域左下和右上坐标，宽高应取坐标差，不能当成四边边距相减。

## 验收边界与剩余工作

**尚未操作 CAD。独立 PC5 的绝对路径加载、绝对 PMP 引用和驱动相对依赖解析未获原生验证。** 代码必须在加载失败、回读路径不同或尺寸不匹配时明确拒绝，不自动修改全局搜索路径，也不改用近似纸张。构建和文件测试不能替代真实出图验收。

AutoCAD PC3/PMP 的压缩格式虽已静态调查，仍未接入自动生成。两宿主的矢量/光栅分辨率、文字转轮廓、PDF 图层信息和外边线控制也不能因找到候选字段就称为已实现；需要单独完成驱动能力与实际输出证据。

后续原生验收需使用明确授权的测试图验证：标准及加长纸、正负和四边留白、混合纸张、已知长度线段、样式、源图及布局恢复、加载拒绝和临时文件清理。图纸来源修订事件噪声与外部配置变化的恢复限制仍见阶段 21。
