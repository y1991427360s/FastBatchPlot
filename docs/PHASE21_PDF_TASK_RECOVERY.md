# 阶段 21：PDF 任务历史与失败页重试

本阶段只推进 PDF 工作流。图章、签名及授权不在目标范围。

## 功能与架构

- 主窗口新增“PDF任务历史”，展示最近更新的 200 条记录；详情只读呈现每页结果、文件路径、原设备/样式/纸张/比例与错误。查看不会打印，也不会改当前主窗口列表。
- 正常使用时记录保存到 `%APPDATA%/FastBatchPlot/tasks/<任务ID>.json`（相对于实际 settings.json 的同级 tasks 目录）。任务开始前、每页调用前和结果确认后原子落盘；离线无设置路径的窗口不写用户目录。
- Core 的 PdfTaskHistory 使用专用版本化 DTO；只保存 PDF 所需快照，不写图章资产或授权凭据。纸张、标题、裁切、比例、来源文档/空间和顺序独立持久化。
- 每个成功单页记录 SHA-256 和大小；恢复时重新核验文件内容、页数、有效纸面尺寸与裁切范围。成功页跳过 CAD，仅重新提交未完成页。
- 成功页缺失或变更、未完成目标出现未知文件、设备/样式消失、路径冲突或来源身份不符时拒绝恢复。不会把崩溃后遗留文件自动认成成功，也不自动覆盖。
- 详情中的“重试未完成页”使用原任务快照，与当前主窗口的设置无关；原批次所有单页成功后按原顺序合并。取消或部分失败不生成不完整合并。
- 单页全部完成而合并失败/取消时，可不连接 CAD 重新合并。此操作核验历史 PDF 本身，不重新证明原 DWG 内容一致性；已成功合并的记录不会再覆盖输出。
- 历史文件使用原子替换和 Revision 乐观并发，整个原任务或恢复过程还持独占运行锁。另一窗口同时恢复同一任务会在输出前被拒绝。
- JSON 限制 16 MiB、最多 10000 页、嵌套/字段长度；拒绝未知/重复字段、版本错误、尾随内容、非规范绝对路径、Windows 保留名、NTFS 数据流和跨输出目录的路径。

## 来源核验边界

两宿主新增 ICadRevisionHost。会话随机标识、文档实例身份、数据库文件路径及 ObjectModified/Appended/Erased/Unappended/Reappended 事件计数组成变更标记。另存可能保留同一 Document，所以路径也参与比较。

有变更标记的首次任务及重试均逐页核验；自动合并前再次核验。图纸会话重开、修改记录改变或旧记录缺少标记时不自动重新绑定。自定义宿主没有此接口时仍可生成任务记录，但不能依据该记录自动重试 CAD 页面。

**这些标记不是 DWG 或全部依赖的内容摘要。** 外参、字体、PC3/PC5、CTB/STB 等外部文件变化不能仅靠数据库事件证明；详情直接提示这些文件更改后应新建完整批次。打印自身的布局/视图恢复也可能触发事件，当前保守拒绝继续复用，不刷新基线来隐藏变更。该事件噪声及宿主消息循环行为尚待原生验证。仅有离线结果不能断言原生恢复流程已经可交付。

跨 CAD 重启的自动续打仍未实现；后续需要源 DWG 与依赖内容证据、未保存修改策略及图框重新绑定。重启后可查看历史，或仅重新合并完整可信的历史单页。
