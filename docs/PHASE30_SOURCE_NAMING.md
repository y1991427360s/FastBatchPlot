# 阶段 30：来源文件命名与书签快照

## 发现的问题

主窗口刷新列表、编辑图号、重新生成文件名时，原来统一调用当前宿主 GetCurrentDocumentName。列表来自 A.dwg，切换活动文档到 B.dwg 后刷新，使用 `{DwgFileName}` 的自动命名可能变为 B。既有文档身份校验能阻止错图打印，但无法阻止名字被当前图纸污染。

## 修改

- 两宿主采集块、多段线、二维多段线和手工范围时记录来源文件基本名，不保存完整目录。
- 图框候选、通用识别和模板识别向 PlotFrame.SourceFileName 传递来源；列表刷新只读取图框快照，不调用当前文档命名接口。
- 来源文件名只用于显示/命名，不代替 SourceDocumentId 和 SourceLayoutId 的会话身份校验，不凭文件名重新绑定文档。
- 文件命名、PDF 书签新增/支持 `{DwgFileName}` / `{文件名}` / `{图纸文件}` 和 `{Layout}` / `{布局}`。
- 来源信息随冻结任务和磁盘历史保存。首次合并与历史重合并使用同样的快照。旧历史缺少字段时使用空来源，格式化为 `Drawing`，不读取当前图纸猜测。
- 历史逐页详情展示来源文件和布局。取消、刷新、模板名称生成和人工文件名覆盖行为保持不变。
- 来源名、图名包含花括号时作为字面文字，不进行二次模板展开；文件名中的路径字符继续清洗，书签保留标点。

## 验证

503 项核心、310 项离线 UI 检查通过。原测试中两条“拒绝 DWG 书签占位符”用例因新增支持而移除，新增三条来源命名/检测/历史检查，因此总数不是简单累加。离线假宿主文件为 test.dwg，列表来源为两份不同原图；刷新、编辑和脱离宿主后名称均保持各自来源，人工名称也保留。
