审查日期：2026-09-20。审查目录：`E:\366256\vibecoding\批打印-new`。

本报告仅依据源码、部署脚本与原版手册 `BPHelp.txt`。没有启动、连接、调用或操作 AutoCAD / ZWCAD，没有运行安装器。以下“原生验收”都是未来取得明确 CAD 验证授权后执行的项目，不代表已经通过。

## 已确认缺陷

### C01 — P1：修改图幅只改名称，实际仍可能按旧纸张输出

- 证据：`src/FastBatchPlot.UI/Views/BatchPlotForm.cs:521-528`、`:549-557` 仅设置 `DetectedPaper.Name`；`PaperSize.WidthMm/HeightMm` 是独立属性（`src/FastBatchPlot.Core/Models/PaperSize.cs:11-15`）。`src/FastBatchPlot.ZWCAD/ZwCadPlotEngine.cs:223-257` 优先按 WidthMm / HeightMm 匹配介质，AutoCAD 同逻辑位于 `AcadPlotEngine.cs:219-252`。
- 触发：识别为 A1 的图框在列表中改为 A3，打印机同时提供 A1 和 A3。界面和文件名变 A3，但物理匹配仍命中 A1。
- 进一步影响：`PaperSizeDetector.cs:115` 将 bestPaper 直接指向 StandardSizes 内对象，`:132` 横向结果不克隆；所以横向同图幅共享可变纸张对象，改一个名称可能污染其他 frame 和全局标准图幅目录。修复时必须同时消除共享可变对象。
- 修复：图幅选择解析为完整纸张值对象，统一更新宽、高、标准名称和方向；未知名称必须显式输入尺寸或拒绝。
- 原生验收：A1 改 A3，验证 PDF MediaBox 为 420 × 297 mm，而不只检查列表文字。

### C02 — P1：出图比例编辑未接入打印比例

- 证据：界面 `BatchPlotForm.cs:532-539`、`:564-575` 更新 CalculatedScale；两个引擎分别在 `ZwCadPlotEngine.cs:164-166`、`AcadPlotEngine.cs:160-162` 无条件使用 `ScaleToFit`。CalculatedScale 在打印引擎仅用于边距换算（中望 `:129`、AutoCAD `:127`）。
- 触发：把 1:100 改成 1:50，零留白时实际打印管线没有任何不同；图名可能变了，工程比例没有变。
- 修复：明确区分精确比例与布满纸张两种模式，前者设置自定义比例并检查可打印区域，比例变化需同步纸张尺寸策略。
- 原生验收：打印已知 10000 图形单位线段，验证 1:100 与 1:50 分别为 100 mm 与 200 mm。

### C03 — P1：留白语义与原版相反，负值可能裁剪内容

- 证据：`BPHelp.txt:49-51` 规定正值放大纸张且保持比例，负值保持纸张并缩小内容。`ZwCadPlotEngine.cs:129-135` / `AcadPlotEngine.cs:127-133` 用正负边距扩缩打印窗口，但不改变纸张；后续又 ScaleToFit。
- 触发：输入 +2 mm，当前方案扩大内容窗口并缩小图形，纸张不变；输入 -2 mm，窗口向内裁切且图形放大，边框可能缺失。
- 修复：将纸张尺寸、图形窗口、输出比例与可打印区域作为单独量计算，按原版定义实现正、负留白。
- 原生验收：A1 +2 mm 输出 845 × 598 mm 且比例不变；负值输出仍 A1 且保留完整边框。

### C04 — P1：打印忙碌时跳过任务却返回成功

- 证据：中望 `ZwCadPlotEngine.cs:184-205` 只有 NotPlotting 才执行，其余状态直接走到 `return true`；AutoCAD `AcadPlotEngine.cs:180-201` 相同。UI `BatchPlotForm.cs:767-771` 据此标成功并将路径交给 PDF 合并；没有验证产物本次生成。
- 触发：宿主正在打印、存在尚未完成的打印任务。可能漏页，甚至把输出目录里上次留下的同名旧 PDF 合并进新成果。
- 修复：忙碌返回明确失败或排队；每次任务用隔离临时目录和唯一文件名，验证新文件存在、可读、页数后才算完成。
- 原生验收：宿主忙碌时提交，不能出现成功状态；预置旧同名 PDF 时不能将它当本次结果。

### C05 — P1：跨图纸、跨布局切换会把旧列表坐标打印到当前图纸

- 证据：`ZwCommands.cs:39-58` / `AcadCommands.cs:39-58` 共用静态无模式窗口；`BatchPlotForm.cs:19` 只保留全局 frame 列表。中望打印 `ZwCadPlotEngine.cs:95`、`:116-120` 每次取当前文档及当前空间；AutoCAD 同类逻辑。`PlotFrame.cs:39` 虽有 LayoutName，适配与打印没有用它绑定来源，也没有文档标识。
- 触发：在图 A 搜索图框，切到图 B 或其他布局，再按打印。旧名称和旧坐标会用于新图内容。
- 修复：识别结果保存文档会话标识、数据库标识、布局标识和实体 Handle；执行前校验来源，切换时切换对应列表或明确失效；禁止通过当前活动文档隐式选择打印来源。
- 原生验收：A/B 两图与模型/布局交叉切换，结果必须来自所选任务的源图、源布局。

### C06 — P1：点击表头排序后，编辑、勾选、删除和定位可能作用于错误图框

- 证据：`BatchPlotForm.cs:128-135` 使用默认可排序的 DataGridViewTextBoxColumn，没有禁用默认排序，也没有行对象绑定。`:499`、`:554-557`、`:580-585`、`:592-599`、`:655-659` 都用显示行 Index 索引 `_frames`，但用户点击表头只排序 grid 行，不同步 `_frames`。
- 触发：按图号列点击排序后，取消第一行勾选、修改图幅、定位或删除。用户操作显示的图框与实际 frame 可能不同。
- 修复：每行绑定稳定 frame ID/对象，所有事件通过绑定对象操作；或完全禁用默认表头排序并只允许统一排序服务。
- 原生验收：准备逆序图号，点击表头排序后逐项验证勾选、编辑、删除、定位对应同一实体。

### C07 — P1：真实纸张打印、多输出格式并未接通

- 证据：原版 `BPHelp.txt:7`、`:104-110` 支持真实纸张以及 PDF/DWF/JPG/PNG/PLT/EPS/SVG。当前 `BatchPlotForm.cs:763` 固定 `.pdf`，`:784-791` 固定 PDF 合并；中望 `ZwCadPlotEngine.cs:189` / AutoCAD `AcadPlotEngine.cs:185` 固定 `plotToFile=true` 且份数 1。`PlotConfig.cs:24` 的 ExportFormat 无消费方。
- 触发：用户选择实体打印机或 DWF/图像设备，当前仍按照 PDF 文件路径、PDF 合并处理，无法提供正常实体纸张批印和对应格式成果。
- 修复：按输出能力拆分纸张打印、PDF、其他文件格式；各自校验设备、扩展名、份数和后处理，PDF 合并只用于 PDF。
- 原生验收：实体打印机 2 份、DWF、PNG、PDF 分别验证，输出格式应以文件签名而非后缀认定。

### C08 — P1：自动识别把多段线图框与块图框互斥处理，可能漏图

- 证据：`BatchPlotForm.cs:403-404` 同时取得两类候选，但 `:409-451` 只要存在任何块图框就不使用 polyFrames；无标题属性时 `:429-440` 只留下一个 dominantBlockName。`:456-458` 固定过滤最大图框面积 10% 以下的框。

- 修复：用合并池与可解释置信度筛选，用户可设/关闭过滤；不要将“最大块一定是图框”当无条件规则。
- 原生验收：同图中混用 A0/A4、两种块名与多段线，明确应保留的清单，核对没有漏图。

### C09 — P1：指定图块不存在时退回所有块，违背筛选承诺

### C10 — P1：纸张不支持时静默降级，任意尺寸/加长纸张没有实现

- 证据：`ZwCadPlotEngine.cs:260-301` 找不到尺寸先截去加长后缀按 A 系列寻找，再退回 mediaList[0]；AutoCAD `:255-295` 相同。没有创建任意尺寸纸张；原版手册 `BPHelp.txt:6` 明确任意尺寸纸张。

- 修复：介质匹配必须返回实际尺寸及偏差，缺失时明确阻止或经用户选择替代；实现经验证的自定义纸张能力。
- 原生验收：打印 1261 × 594 mm 加长图与 500 × 100 mm 自定义图，测量 PDF 页尺寸。

### C11 — P1：部分或全部失败时仍弹出成功/完成提示

- 证据：`BatchPlotForm.cs:775` 只记录单行失败；`:793-796` 即使部分页面失败也显示“打印与合并全部完成”“批量打印成功完成”；`:804-807` 全部失败、零成功时也显示完成。

- 原生验收：人为令一页失败与全部失败，状态、提示和成果清单应准确一致。

### C12 — P2：手动输出名称会被刷新覆盖，重复名称没有防护

- 证据：`BatchPlotForm.cs:543-544` 支持手改，`:630` 每次刷新无条件重新模板生成；排序、删除、打印结束都会 RefreshGrid。`:763` 直接以名称生成最终文件路径，无重名规划、路径清洗或现存文件策略。
- 触发：手工命名后重新排序，名字消失；多个图框改为同名，打印将覆盖、报错或合并错误内容；手工输入绝对路径/分隔符可能逃离输出目录。
- 修复：将手工覆盖名称与模板预览分开保存；整个任务开始前计算唯一合法路径，明确覆盖策略，采用临时输出后原子提交。
- 原生验收：手改名后排序、删除、完成打印均保持；同名、非法字符、路径分隔符和现有文件均得到清晰处理。

### C13 — P2：打印执行缺少任务隔离、取消与可靠清理

- 证据：`BatchPlotForm.cs:752` 仅禁用开始按钮；`:761` / `:788` 使用 DoEvents，其他控件和窗口仍可交互；`:730-812` 没有 finally、取消令牌或统一异常处理。输出目录创建 `:742` 在任何保护之外。

- 修复：执行前生成不可变任务快照；CAD 操作留在宿主要求线程，采用串行调度与明确取消点；禁用会改变任务的操作，finally 恢复状态；不要简单把 CAD API 放 Task.Run。
- 原生验收：打印过程中尝试修改和关闭；中途取消；不可写目录和异常后界面能恢复，结果状态不混淆。

### C14 — P2：打印样式设置失败被吞掉

### C15 — P2：部署脚本绑定开发机和 Debug 目录，版本支持范围没有依据

- 证据：`deploy/Install-AutoCAD.ps1:9,22-23`、`Install-ZWCAD.ps1:12,43` 硬编码 E 盘开发路径；后者直接把 Debug DLL 注册为加载路径且不复制发布包。`Install-ZWCAD.ps1:5` TargetVersion 参数未使用，`:26-52` 注册 2020—2026 及 HKLM，编译却只引用 `FastBatchPlot.ZWCAD.csproj:24,28` 的 2026 SDK。`PackageContents.xml:14` 宣称 R19.0—R25.0，AutoCAD 项目 `:4,22-32` 实际是 net48 + AutoCAD 2018 SDK；AutoCAD 2025 的 .NET 8 宿主需要独立适配构建，不能据该清单宣称兼容。脚本没有 ErrorActionPreference=Stop，写注册表失败后仍可计数并输出成功。

- 原生验收：干净机器/隔离账号安装、卸载、升级；每个声称支持版本分别验证加载与最小打印。当前未做任何兼容性原生验收。

## 功能缺口与架构事实

1. **模型/布局遍历缺失**：原版 `BPHelp.txt:15,66,83,95` 明确支持；两个 Adapter 的 `Collect*` 都只遍历 CurrentSpaceId（例如 `ZwCadAdapter.cs:46,68`），没有遍历 LayoutDictionary。布局名字段存在不代表功能接通。
2. **任意两点矩形范围打印缺失**：ICadHost 只有实体选择；PlotFrame 有 PickWindow 枚举，但没有窗口两点采集实现。原版手册第一种基本打印方式需纳入功能矩阵。
3. **按图层筛选未接通**：`ICadHost.cs:22` 的 layerFilter、`:27` 的 blockNameFilter 在两个适配器中未使用；UI 点选返回 layerName（`BatchPlotForm.cs:325`）后忽略它。原版 `BPHelp.txt:118-122` 有明确图层筛选。
4. **签名、印章开关是孤立模型字段**：`PlotConfig.cs:61,66` 在产品代码没有消费者，没有签名/印章库及其授权流程。原版 `BPHelp.txt:170-188` 有实质功能。不能以两个布尔属性标注为已支持。
5. **外边线开关、方向开关、书签模板缺少完整接入**：PrintOuterBorderLine / AutoOrientation 无消费方；UI 书签仍硬编码（`BatchPlotForm.cs:771`）。
6. **打印预览未实现**：双击调用 `ZoomToFrame` 是 CAD 定位，不是按打印配置生成的预览；没有 PrintPreview 引擎流程。原版 `BPHelp.txt:62,91` 有预览。
7. **标准图框仅画矩形**：`ZwCommands.cs:142-153` / 对应 AutoCAD 命令没有从 resources 加载带属性标题栏模板；不等同原版图框编辑和插入能力。
8. **真彩转索引范围有限**：`ZwCommands.cs:74-90` 只遍历当前空间顶层实体，未处理图层真彩、块内实体与嵌套属性，因此不能承诺整图全部真彩统一转换。
9. **重复扫描与重复实现**：自动检测分别调用两次 Collect（UI `:301-302`），每次又同时提取多段线与块（Adapter `:38-50`、`:60-72`），同一图被扫描两遍。两套 CAD Adapter、Commands、PlotEngine 大面积复制，业务错误同步出现。建议抽出一次候选快照、纯函数的打印规划与共用调度，再保留薄宿主适配层。
10. **版本和设置持久化不足**：当前 UI 每次 new PlotConfig，没有设置仓储或任务恢复服务；源目录 config 不能自动视作已接入。应明确验证哪些设置能跨会话保留。

## 需要原生验证才能定论的风险

- 打印窗口坐标：采集包围盒为实体/世界坐标，`SetPlotWindowArea` 通常需要当前显示坐标系；当前无视图变换。旋转 UCS、视图扭转、倾斜图框需要专项验证。不要仅凭普通平面图通过就宣称全部坐标系兼容。
- Polyline.GetPoint2dAt 是实体平面坐标，当前未处理 Normal/Elevation/OCS；非默认实体平面需测试。
- 模型/布局的窗口打印限制、当前浮动视口状态、BACKGROUNDPLOT 与 PrintEngine 生命周期均无专项验收证据。
- 无模式窗口直接调用 Editor.GetSelection / GetEntity 的交互上下文是否在各宿主版本安全，需验证。
- UI 顶部单行 FlowLayoutPanel 不换行、固定高度（`BatchPlotForm.cs:65-70`），工具较多，底部也用固定高度；高 DPI 下是否裁剪必须渲染验证。不能以未经验证的描述宣称新 UI 比原版更适配 4K；原版升版说明已记录 2025-10 的 4K 修复。

## 推荐修复顺序

先建立可测试的不可变打印任务模型（来源文档/布局、坐标变换、精确尺寸和比例、格式、样式、输出路径），修 C01—C06、C10—C11；再接通实体打印和格式分支；再补齐原版工作流；最后做宿主分版本打包、取消/恢复与交互优化。WinForms 或 .NET Framework 本身不是失败原因；宿主插件必须尊重 CAD 运行时，现代化应落在边界、任务状态、测试与可恢复性上。
